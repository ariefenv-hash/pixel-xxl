# Pixel XXL（Pixel.XL.0827.html）深度分析报告

> 分析对象：md3 仓库 Release `nnnj` 附件 `Pixel.XL.0827.html`（57,470,525 B）
> 分析方式：实际下载 → 复现 TurboWarp Packager base85 解码逻辑提取内嵌 zip（44,129,064 B）→ 解包 329 个素材 + project.json（1,054,272 B）→ 全量反编译 6,162 块积木为可读伪代码逐脚本核对
> 配套材料：`qwq1018.js`（863 行，GPU 液态玻璃扩展 v4）单独比对

---

## 1. 文件本体：它是什么、怎么打包的

- **TurboWarp Packager 打包的 Scratch 单文件工程**（`<title>Pixel XXL</title>`），双击即玩、零依赖、可离线。
- 打包形态：Scratch 运行时（Scaffolding + VM + 渲染器）+ 11 个扩展源码 + 工程数据全部内联进一个 HTML。
- 工程数据以 **674 个 base85 分块 `<script data="…">decodeChunk(N)</script>`** 内嵌，解码后为 44,129,064 B 的 zip（本次分析用 Python 1:1 复现其 `getBase85DecodeValue`（`(`/`)` 重映射到 `<`/`>` 后 `code-0x2a`）+ 小端 uint32 逻辑完整提取，PK 头校验通过）。
- 舞台分辨率 **324×720（9:20 手机比例）**，`preserve-ratio` 缩放——一台"Pixel 手机"的画布。
- 启动流程：加载进度条 → 点击启动屏 → 运行。点击前 VM 已把 zip 读入内存（`PROJECT_LOADED` 后置空 zip 供 GC）。

## 3. 项目定性：用 Scratch 写的 Android 手机操作系统模拟器

一个可交互的「Pixel 手机」：**174 帧开机动画 → 系统预热（预渲染/取色）→ 三页开机引导 → 桌面（双页 + 时钟大图标 + 页面圆点）→ All Apps 抽屉 → 应用窗口打开/后台卡片/侧滑返回 → 锁屏（a/d 键）→ 控制中心 → 动态壁纸模糊**。内置 8 个应用：设置、相册、商店、通知、视频、电话、bilibili、个性化、music（真实可播 2 首：fripSide - only my railgun、蛋仔汤音 - 刀酱《520AM》）、计算器（完整按键布局 + 按下态）、时钟（动态表盘图标：时针/分针/秒针按当前时间实时旋转，克隆三层实现）。

### 各角色职责（实测划分）

- **角色2**（178 造型）：开机动画帧序列（174 次"下一个造型"逐帧播放），播完设置 `开机动画中？=1`，等所有图标预渲染完（`渲染的进度 ≥ 渲染数`）→ 广播 `app加载` → 等取色完（`取色进度 ≥ 目标取色数量`）→ 广播 `开机引导下一页`。它就是**系统引导程序**。
- **应用**（58 造型，1768 块）：桌面图标引擎。`克隆应用` 过程按 x/y/大小/页数 克隆 11 个图标实例；`多层图标` 过程把图标拆成 主图标+文字层（+长图标再拆上下两段），时钟图标再拆出时/分/秒针三层克隆；克隆体启动时**预渲染 61 张裁切皮肤**（20+20+21 次 `裁切URL` 注册，圆角从 180 递减、裁切高从 440 递增）——这是"图标→全屏窗口"连续变焦动画的**预计算帧序列**，播放时只换皮肤，零卡顿。
- **触控**：桌面滑动分页（页宽 324，越界阻尼 ÷5）、后台卡片横向滑动（位移 ×1.5 跟手）、底部上滑进后台（y<-342 起手，y>-300 判回弹）。
- **APP-基本结构 / 个性化APP / music APP / 计算器 APP**：应用本体。每个应用都是一个"控件工厂"：`克隆 控件名称 类型` 按类型（tc=图层登记 / 0=底层 / 1=触控热区 / 2=菜单页 / 3=md3e-返回柄 / 4=实体按键）克隆出整个 UI；`{应用}-应用状态` 状态机字符串（如 `1-{关于本机}`、`2-{彩蛋}`）驱动页面路由。
- **zz**（7 造型）：壁纸层。引导结束前叠 60 帧云母模糊 + 亮度渐入；此后常驻循环：桌面态模糊 → 0，进应用/后台/抽屉 → 16 级（All Apps 抽屉按 `显示y` 连续插值 0~48）。
- **All Apps**：抽屉（从 -695 滑入），一次性关闭逻辑（返回键/锁屏/进应用即复位）。
- **交互方式**：全局返回手势（屏幕底部 y<-320 按下 → `返回按键=1`，10 帧后自动清零）。
- **开机及引导**：3 页引导（每页 5~13 个克隆元素带视差入场：x2/y2 目标位插值、大小渐变、云母模糊 7→0 收敛），"next" 按钮点击翻页，第 3 页后广播 `引导结束`。
- **角色1**：每帧置顶的调试小帮手（仅 3 块）。

## 4. 三大核心技术（本工程最有含金量的部分）

### 4.1 Material You 动态取色管线（Scratch 实现的 Monet）

实测调用链（应用 + 各 APP 的 `染色` 过程，全工程 `materialPalettePro_generate` ×47、`replaceColors` ×47）：

```
壁纸 SVG 造型内容
  → 多层 lmsLooksPlus_replaceColors（把设计稿固定色 #535980/#6a6f8e/#8f94b3 等逐层中和，实测嵌套 3 层）
  → svgconvert_toDataUrl（SVG 文本 → dataURL）
  → materialPalettePro_generate（average/median/kmeans 三算法取基色 → HSL → 生成 light/dark 各 10 档 tonal palette JSON：键 50~900，极端亮度饱和度 ×0.8）
  → skyhigh173JSON_json_get(json, 'light') → json_get(json, 亮度模式+100)（按「亮度模式」变量 100/500/600/800 选 tone 键）
  → lmsLooksPlus_replaceColors(控件SVG, 旧色, 新tone色) 逐控件重染
```

配套**取色进度门控**：每个控件染色时 `目标取色数量`/`取色进度` 计数（存档值 64/68），`取色` 广播后壁纸切换 → 全 UI 重染。换壁纸（个性化 APP 选 7 张）→ 广播 `壁纸` → `壁纸编号` 切换 → 全链重跑。**这就是一套跑在 Scratch 里的 Material You 动态主题引擎**，与 md3 仓库的 `monet.js`/`theme-engine.js` 是同构思路的 Scratch 版。

### 4.2 预渲染变焦动画（61 帧 skin 序列）

打开应用的"图标放大成窗口"动画不是实时计算的：每图标预注册 **61 张不同裁切高度/圆角的皮肤**（`lmsSkins_registerURLSkin(cropURL(造型内容))`），播放时按 `填充图标宽/长` 插值直接 `将皮肤设为`。代价是启动时 11 图标 × 61 张 = **671 张皮肤**的预计算（`渲染数=671` 与存档值精确吻合），收益是打开动画全程 60fps。曲线还分两套风格（`曲线风格 0/1`：开窗指数趋近 vs 变速宽/长分阶段缓动）。

### 4.3 云母片模糊（qiaoqiaoMica，作者自写扩展 17KB）

CPU 路线：`canvas 2D ctx.filter=blur()` 重绘当前造型 → `createBitmapSkin` 换肤。工程化很完整：**任务队列串行化**（无防抖立即入队）、**每 drawable LRU 缓存**（缓存容量/降采样级别/自动预加载三积木）、错误边界、`requestAnimationFrame` 渲染节流、4096² 像素硬上限。壁纸模糊 0↔16 级全靠它 + 缓存命中。

## 6. qwq1018.js（GPU 液态玻璃 v4）与工程的关系 —— 关键结论

**`Pixel.XL.0827.html` 构建内完全不含该扩展**（全文 `GPULiquidGlass`/`qwq1018` 0 命中；打包器注入的 11 项 = project.json 的 11 项，无第 12 个）。即：**玻璃扩展是打包之后单独开发的下一步方案，尚未集成**。与已在用的 qiaoqiaoMica 对比：

| | qiaoqiaoMica（在用） | gpuLiquidGlass v4（未集成） |
| --- | --- | --- |
| 渲染路线 | CPU canvas 2D blur，换 bitmap skin | WebGL2 双 pass 着色器（GLASS_VS/GLASS_FS/BLIT_VS） |
| 效果 | 整张造型模糊（毛玻璃/云母） | 折射+色散+边缘反光+着色的**液态玻璃**，跟随角色 |
| 参数面 | 模糊值/缓存/降采样 3 项 | 十四参数（折射高度/折射量/玻璃模糊/边缘模糊/色散/着色强度/边缘反光/上下反光/反光粗细/亮度/白点/对比度/饱和度/圆角平滑度）+ 正常玻璃/G9线框双模式 |
| 几何 | 无（整张糊） | 超椭圆 p-norm SDF：平滑度 s∈[0,100]→阶数 n=2.5+3.5(s/100)（s≈43 即 Apple squircle G3），R≥min(W,H) 时"圆化"行为收缩成真圆 |
| 性能手段 | 队列/LRU/降采样 | 整屏 blit 一次回写、scissor 包围盒限绘、GL 状态完整保存恢复、出画跳绘、色散按需（<0.01px 复用）、边缘反光只在窄环算 |
| 加载要求 | 普通模式即可 | 必须 unsandboxed（直接拿 renderer._gl） |

演进判断：v4 头注自述 12 条改动全部是结构优化（自称不改默认视觉），其中 #10/12（超椭圆 + 圆化）实际是几何修正。若集成进 Pixel XXL，替代面就是 `zz` 的壁纸模糊 + 开窗玻璃层——但要注意它绑定角色包围盒，与现有"61 帧预渲染 skin"管线是两套并存方案。

## 7. 工程质量评价

**亮点**：
1. 克隆即组件的 UI 框架（控件工厂 + 状态机字符串路由），在 Scratch 里实现了一整套"窗口管理器"：后台卡片用 `e^` 指数函数排布（`200+90*e^(0.001*((序号-1)*(-160)+后台x))`）、层级用列表 `触控判断-后台图层` 做命中测试——这连浏览器版 md3 都是一整套模块（split-screen/recent-apps/taskbar-core）的活。
2. Material You 取色管线完整度高（生成→存储→按亮度模式取 tone→全 UI 重染→进度门控），含 light/dark 双档。
3. 预渲染换帧动画思路（61 帧 skin）是对 Scratch 渲染瓶颈的正确工程化回应。
4. 自写扩展的工程质量好于绝大多数社区扩展：有缓存、队列、错误边界、内存上限。

**短板 / 风险（实测）**：
1. **112 个监视器全开**（`渲染数=671` 存档值即来源于此），打包运行时它们被隐藏但仍占序列化体积；调试变量残留多（`测试2/测试3/测试-可删/测试-后台2/我的变量/我是2`）。
2. **坐标硬编码布局**：触控热区全部是 `abs(鼠标x-0)<147.5 且 abs(鼠标y-206)<34` 一类魔数（设置页/个性化页十几处），改 UI 尺寸需全局手调——md3 侧的教训（`#229 摸底`）在这里同样成立。
3. 体积失控点明确：5 张照片壁纸 30+MB。若发正式版应压成 PNG/WebP（其 SVG 壳只是 base64 容器）。
4. 顶层游离脚本较多（x/y=(0,0) 的散装 `将变量…设为` 25 处，如 亮度模式 500/100/800、曲线风格 0/1、手势返回大小 100/20——疑似被"停止此脚本"截断的调试开关）。
5. `开机引导页` 存档值='4'、`锁屏='0'` 等运行态被随包保存，首次启动会从中间态进入（角色2 引导有兜底重置，实测链路可自愈，但属于应清理的脏存档）。
